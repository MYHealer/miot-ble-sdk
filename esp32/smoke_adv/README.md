# 米家烟雾传感器（mirsz.sensor_smoke.s500）小白版固件 —— ESP32-C3

**一根 Type-C 线、三条命令、串口一条命令就能用。**

烧完这块板子在你的米家里就变成一台「烟雾传感器」：米家 App 能添加它、
设备页能看火警状态（正常/报警），还能拿它当自动化触发条件（火警 → 报警/推送）。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连）
- 模拟型号：烟雾传感器 `mirsz.sensor_smoke.s500`，PID **0x392E**（国区 pdid 14638）
- 上报内容：火警 `0x482B`（1B bool，0=正常 1=火警）
- 通道：MiBeacon V5 加密**广播**（网关收） + 0xFE95 GATT（只用于绑定）

> 只想知道原理不用烧板子：看 [`../t3pro_adv/README.md`](../t3pro_adv/README.md)。
> 本工程与 gas_adv 骨架相同，只有 PID / 广播对象号 / 载荷类型不同，代码里都标了 ★。
>
> **2026-11-17 实机验收通过**：米家添加 3/3 完成（did `00 62 6C 74`），设备页
> 「烟雾传感器 / 设备状态 正常」+ 历史「烟雾报警解除」；串口 `alarm 1` → 云端 `2:1043 = true`（双向验证）。

## 一、动手前先看这三行

| 你要做的 | 怎么做 |
|---|---|
| 火警正常 / 报警 | 串口发 **`alarm 0`** / **`alarm 1`**（或 `toggle` 切换、短按 BOOT） |
| 恢复出厂（重新添加） | **按住 BOOT 5 秒**（串口打印「恢复出厂」后自动重启） |
| 看它有没有在干活 | 串口每触发一次都有 `>>> 串口设火警 = 1` |

不用接线、不用改代码、不用装别的库。

## 二、编译（二选一）

**装了 ESP-IDF v6.0：**

```bash
cd esp32/smoke_adv
idf.py build
```

**没装 IDF，用 Docker（推荐，不用配环境）：**

```bash
docker run --rm -v "D:/workspace/temp/miot-ble-sdk:/project" -w /project/esp32/smoke_adv \
  espressif/idf:v6.0 bash -c "idf.py build"
```

## 三、烧录（第一次一定要擦）

```bash
idf.py -p COM6 erase-flash
idf.py -p COM6 flash monitor
```

**为什么要 `erase-flash`**：NVS 里如果留着别的工程的绑定身份，板子会以「已绑定」
状态广播，米家的添加列表会**直接把它过滤掉**，表现就是「怎么都扫不到」。
换工程、改 PID、重新添加之前，一律先擦。

烧完串口应该是这样：

```
I (143) SMOKE: ===== 烟雾传感器 小白版（SMOKE500 / 0x392E）=====
I (143) SMOKE: 用法：米家 App → + → 添加设备 → 点 SMOKE500 → 绑定
I (333) SMOKE: 协议栈就绪  MAC 10:00:3B:CE:77:05  未绑定（等待米家添加）
```

## 四、在米家里添加

1. 米家 App → 右上角 **+** → **添加设备**
2. 等「附近设备」里出现 **烟雾传感器**（通常 3~10 秒）
3. 点它 → 选房间 → 确认名称 → 完成
4. 回到设备页，串口发 `alarm 1` → 页面「设备状态」变报警，并进「历史记录」

## 五、看现象：三种「成功」的样子

| 现象 | 说明什么 | 判据（串口） |
|---|---|---|
| 附近设备里出现「烟雾传感器」 | 广播 + 未绑定形态对了 | `未绑定（等待米家添加）` |
| 设备页标题「烟雾传感器」+ 历史记录 | 云端按 0x392E 的 spec 正确识别 | 设备页状态「正常」 |
| 串口 alarm 页面状态跟着变 | 广播 → 网关 → 云端全链路通 | `>>> 串口设火警 = 1` |

## 六、★对象号（重点看这段）

烟雾传感器是**新式 spec 设备**，广播对象号不是老式的 0x10xx，而是按公式算：

```
eid = 0x4000 | (siid << 10) | (piid - 1000)
```

| 属性 | spec (siid.piid) | 对象号 | 载荷 |
|---|---|---|---|
| fire-alarm | 2.1043 | **0x482B** | 1B **bool**（0=正常 1=火警） |

**帧构造**：`miot_beacon_obj_u8(objs, 0x482B, v_alarm)`，加密帧 16B（无 MAC 形态）。

**验证坑**：串口设值后必须**保持串口连接**——关串口会让 ESP32 通过
DTR/RTS 复位，v_alarm 回到默认 0。用脚本设值 + 保持期间读云端才拿得到新值。

## 七、改参数（都在 `main/app_main.c` 顶部）

| 想改什么 | 位置 | 说明 |
|---|---|---|
| 型号 / PID | `SMOKE_PID` / `SMOKE_NAME` | 换型号要同步改广播对象号 |
| 广播对象号 | `s_obj_smoke` | 默认 0x482B；可用串口 `obj` 临时改 |
| 火警状态 | `v_alarm` | bool 0/1；串口 `alarm N` 可改 |
| 设备 MAC | `BASE_MAC_B4` | **每个工程必须不一样**，米家按 MAC 去重（smoke 用 0x77） |
| 广播间隔 | `ADV_PERIOD_MS` | 默认 4 秒轮换一帧 |

## 八、串口命令一览

| 命令 | 作用 |
|---|---|
| `alarm 0` / `alarm 1` | 设火警状态（0=正常 1=报警，连发 3 帧事件） |
| `toggle` | 火警状态切换（连发 3 帧） |
| `info` | 打印 PID / MAC / 绑定状态 / 当前火警 |
| `obj XXXX` | 临时改 fire-alarm 对象号（排查用，如 `obj 482B`） |
| `factory` | 擦身份重启（回到未绑定） |

> 注意：`alarm` 是 5 个字母，命令解析用 `strncmp(line,"alarm",5)` + `line+5`。
> 新增多字母串口命令时，长度和指针偏移必须同步，否则参数会被截成 0（本工程实测踩过）。

## 九、常见问题

**Q：米家里扫不到这块板子？**
① 先 `erase-flash` 再烧（最常见）；② 确认 `BASE_MAC_B4` 跟别的工程不同
（door3=0x6F, gas=0x76, smoke=0x77 已各自独立）；③ 手机蓝牙开着，站近一点。

**Q：设备页一直是「--」/「未连接蓝牙网关」？**
烟雾传感器是**纯广播设备**：页面数据走「广播 → 网关 → 云端」，跟手机连不连没关系。
必须有一个在线的蓝牙网关（小爱音箱 / 蓝牙 Mesh 网关）且它愿意收这个品类。

**Q：串口 alarm 设了值，云端没变？**
八成是串口断了导致 ESP32 复位、值回到默认 0。保持串口连接（不要关 monitor/脚本），
再设值并等 5~10 秒网关上报。

## 十、已知边界

- **只有火警一个可读属性**（spec 里 forcibly-removed-alarm / silencers 未实现广播）。
- **火警是模拟值**，没接真实烟雾探头；接真实传感器时替换 `v_alarm` 采样即可。
