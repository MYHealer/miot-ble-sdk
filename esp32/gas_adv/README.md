# 米家燃气传感器（mirsz.sensor_gas.ga500）小白版固件 —— ESP32-C3

**一根 Type-C 线、三条命令、串口一条命令就能用。**

烧完这块板子在你的米家里就变成一台「燃气传感器」：米家 App 能添加它、
设备页能看燃气浓度，还能拿它当自动化触发条件（燃气超标 → 关阀/开窗/报警）。

- 目标芯片：ESP32-C3（USB-Serial/JTAG 直连）
- 模拟型号：燃气传感器 `mirsz.sensor_gas.ga500`，PID **0x392D**（国区 pdid 14637）
- 上报内容：燃气浓度 `0x480B`（float，范围 1~100）
- 通道：MiBeacon V5 加密**广播**（网关收） + 0xFE95 GATT（只用于绑定）

> 只想知道原理不用烧板子：看 [`../t3pro_adv/README.md`](../t3pro_adv/README.md)。
> 本工程跟它一个骨架，只有 PID / 广播对象号 / 载荷类型不同，代码里都标了 ★。
>
> **2026-11-17 实机验收通过**：米家添加 3/3 完成（did `00 62 6C 74`）→
> 推荐场景自动出现「燃气超标提醒」（云端按 spec 正确识别）→ 设备页「燃气浓度 3%」；
> 串口 `gas 35` → 云端 `2:1011 = 35`（双向验证）。

## 一、动手前先看这三行

| 你要做的 | 怎么做 |
|---|---|
| 浓度正常 / 报警 | 串口发 **`toggle`**（在 2.5 / 35 间切换），或短按 BOOT |
| 设任意浓度 | 串口发 **`gas N`**（如 `gas 50`，float 1~100） |
| 恢复出厂（重新添加） | **按住 BOOT 5 秒**（串口打印「恢复出厂」后自动重启） |

不用接线、不用改代码、不用装别的库。

## 二、编译（二选一）

**装了 ESP-IDF v6.0：**

```bash
cd esp32/gas_adv
idf.py build
```

**没装 IDF，用 Docker（推荐，不用配环境）：**

```bash
docker run --rm -v "D:/workspace/temp/miot-ble-sdk:/project" -w /project/esp32/gas_adv \
  espressif/idf:v6.0 bash -c "idf.py build"
```

## 三、烧录（第一次一定要擦）

```bash
idf.py -p COM6 erase-flash
idf.py -p COM6 flash monitor
```

**为什么要 `erase-flash`**：NVS 里如果留着别的工程的绑定身份，板子会以「已绑定」
状态广播，米家的添加列表会**直接把它过滤掉**，表现就是「怎么都扫不到」。
换工程、改 PID、重新添加之前，一律先擦。

烧完串口应该是这样：

```
I (144) GAS: ===== 燃气传感器 小白版（GAS500 / 0x392D）=====
I (144) GAS: 用法：米家 App → + → 添加设备 → 点 GAS500 → 绑定
I (334) GAS: 协议栈就绪  MAC 10:00:3B:CE:76:05  未绑定（等待米家添加）
```

`未绑定` 就对了 —— 说明它在等 App 来添加。

## 四、在米家里添加

1. 米家 App → 右上角 **+** → **添加设备**
2. 等「附近设备」里出现 **燃气传感器**（通常 3~10 秒）
3. 点它 → 选房间 → 确认名称 → 智能场景页应出现「**燃气超标提醒**」→ 完成
4. 回到设备页，串口发 `gas 35` → 页面「燃气浓度」变成 35%

> 「燃气超标提醒」这个场景是**云端按 spec 正确识别的铁证**——
> 如果绑定后被认成别的型号（比如温湿度计），这里不会出现燃气场景。

## 五、看现象：三种「成功」的样子

| 现象 | 说明什么 | 判据（串口） |
|---|---|---|
| 附近设备里出现「燃气传感器」 | 广播 + 未绑定形态对了 | `未绑定（等待米家添加）` |
| 场景页出现「燃气超标提醒」 | 云端按 0x392D 的 spec 正确识别 | 设备页标题「燃气传感器」 |
| 串口 gas 页面浓度跟着变 | 广播 → 网关 → 云端全链路通 | `>>> 串口设浓度 = 35.0` |

## 六、★对象号（重点看这段）

燃气传感器是**新式 spec 设备**，广播对象号不是老式的 0x10xx，而是按公式算：

```
eid = 0x4000 | (siid << 10) | (piid - 1000)
```

| 属性 | spec (siid.piid) | 对象号 | 载荷 |
|---|---|---|---|
| gas-concentration | 2.1011 | **0x480B** | 4B **float**（浓度值 1~100） |

**帧构造**：`miot_beacon_obj_f32(objs, 0x480B, v_gas)`，加密帧 19B（无 MAC 形态）。

**验证坑**：串口 `gas N` 设值后必须**保持串口连接**——关串口会让 ESP32 通过
DTR/RTS 复位，v_gas 回到默认 2.5。用 `gas N` + 保持串口期间读云端才拿得到新值。

## 七、改参数（都在 `main/app_main.c` 顶部）

| 想改什么 | 位置 | 说明 |
|---|---|---|
| 型号 / PID | `GAS_PID` / `GAS_NAME` | 换型号要同步改广播对象号 |
| 广播对象号 | `s_obj_gas` | 默认 0x480B；可用串口 `obj` 临时改 |
| 浓度值 | `v_gas` | float，默认 2.5；串口 `gas N` 可改 |
| 设备 MAC | `BASE_MAC_B4` | **每个工程必须不一样**，米家按 MAC 去重（gas 用 0x76） |
| 广播间隔 | `ADV_PERIOD_MS` | 默认 4 秒轮换一帧 |

## 八、串口命令一览

| 命令 | 作用 |
|---|---|
| `toggle` | 浓度在 2.5(正常) / 35(报警) 间切换（连发 3 帧事件） |
| `gas N` | 设浓度值（float，如 `gas 50`） |
| `info` | 打印 PID / MAC / 绑定状态 / 当前浓度 |
| `obj XXXX` | 临时改 gas 对象号（排查用，如 `obj 480B`） |
| `factory` | 擦身份重启（回到未绑定） |

## 九、常见问题

**Q：米家里扫不到这块板子？**
① 先 `erase-flash` 再烧（最常见）；② 确认 `BASE_MAC_B4` 跟别的工程不同
（同一块板子烧过别的工程、且那个 MAC 已经被你的账号绑过，米家会按 MAC 去重）；
③ 手机蓝牙开着，站近一点。

**Q：设备页一直是「--」/「未连接蓝牙网关」？**
燃气传感器是**纯广播设备**：页面数据走「广播 → 网关 → 云端」，跟手机连不连没关系。
必须有一个在线的蓝牙网关（小爱音箱 / 蓝牙 Mesh 网关）且它愿意收这个品类。

**Q：串口 gas 设了值，云端没变？**
八成是串口断了导致 ESP32 复位、值回到默认。保持串口连接（不要关 monitor/脚本），
再设值并等 5~10 秒网关上报。

## 十、已知边界

- **只有燃气浓度一个属性**（spec 里的 self-test / silencers 是只写控制项，未在广播实现）。
- **浓度是模拟值**，没接真实燃气传感器；接真实 MQ 系列时替换 `v_gas` 采样即可。
- 无电量属性（该型号 spec 未定义 battery service 的读属性）。
