# 米家 LED 智能灯泡 蓝牙 Mesh 版（MJDP003）· 小白版固件

> **状态：2026-11-14 编译 + 烧录 + 串口/广播实测通过；PID 已预填 `0x06EB`（推断值），米家绑定待验。**
> 工程 `esp32/bulb_gatt`，734 行（+245 行 GATT 复用），固件 595,184 字节。

这是仓库里第一台**灯具类 spec 设备**：不是广播型传感器，也不是夜灯 2 那种 NUS 文本协议，
而是标准 `siid/piid` 属性帧 —— 和温湿度计同一条链路，只是属性换成灯的三条。

---

## 0. 为什么是这台

| 型号 | 上市 | 蓝牙 | 能不能模拟 |
|---|---|---|---|
| 夜灯 2（MUE4094RT） | 2019 | ✅ BLE 直连（NUS 文本） | 已做，`esp32/nightl2_adv` |
| 夜灯 3（MJYD06YL） | 2024 | ❌ 官方明确「不支持蓝牙、不支持米家」 | **不能** |
| 夜灯 4（2026-09） | 2026-09 | ❌ 同上，纯本地按键 | **不能** |
| **LED 灯泡 蓝牙 Mesh 版（MJDP003）** | **2026-08-31** | ✅ **手机蓝牙直连，无需网关** | **本工程** |

夜灯 3/4 只能做「纯本地固件」（不联网、不进米家）。要找「新一点、又真走 BLE」的灯，
2026 这波里只有这支 29.9 元的灯泡：官方原话是「支持手机蓝牙直连，无需蓝牙网关即可
通过米家 App 进行直接控制」—— 这正是一条 GATT 通道。

**注意它是 Mesh 产品**：多灯组网、网关语音那些功能依赖 Mesh 配网密钥，我们做不到；
但「单灯直连」这条路不需要密钥，和温湿度计一样是 0xFE95 上的 spec 会话。

## 1. 三步上手

### 1.1 编译烧录

```bash
cd esp32/bulb_gatt
idf.py set-target esp32c3
idf.py build
idf.py -p COM6 erase-flash flash
```

启动应该看到：

```
I (145) BULB: ===== 米家 LED 智能灯泡 蓝牙 Mesh 版（MJDP003）=====
I (145) BULB: LED: GPIO8 低电平点亮, 5000Hz PWM（2.2 亮度 → 占空比）
I (385) MIOT-GATT: 0xFE95 service registered (0010/0019/001A/001B)
I (385) BULB: host synced, MAC 10:00:3B:CE:71:05  PID=0x06EB bound=0
```

### 1.2 PID 已预填 0x06EB（推断值，待绑定验证）

公开渠道不给 `MJDP003` 的蓝牙 PID，但 `MJDP003` 是**替换 `MJDP09YL`** 的型号
（同为 E27 5W 500lm 2700–6500K，官方 BHR4861CN）。米家同品类换代通常沿用 pdid，
而 `MJDP09YL` 在 XiaomiGateway3 产品字典里是 **pdid 1771 = `0x06EB`**，所以先填这个值。

判定顺序：`0x06EB` → 失败退 `0x0926`（Yeelight Mesh Bulb M2）→ `0x06EC`（米家 Mesh 筒灯）。

想换号**不用重编译**（运行期可改）：

```
pid 0x06EB      # 写 NVS 并自动重启
pid             # 查当前值
```

> ⚠️ NVS 里的 `pid` 键**优先于**编译默认值。改了 `BULB_PID_DEFAULT` 却没用新值，
> 说明 NVS 里还留着旧号 —— `erase-flash` 或直接 `pid 0xXXXX` 覆盖。

只有 0x06EB / 0x0926 / 0x06EC 全试过都不行，才需要真机扫一帧：

1. 手机装 nRF Connect，扫到名字是 `MJDP003`、服务数据带 `0xFE95` 的那台
2. 看 Service Data 第 3~4 字节（小端）就是真 PID

   ```
   70 28 | eb 06 | 34 | 05 71 ce 3b 00 10 | ...
           ↑↑↑↑
           第 3~4 字节，小端
   ```

### 1.3 米家添加

米家 → + → 添加设备 → 附近设备 → 点这台灯 → 按提示绑定。

绑定成功后串口依次出现：

```
AUTH_INIT → token → BOND → DeviceID → GETRAND → LOGIN 0x21
*** session established: spec channel ready ***
```

## 2. 属性表（对齐 miot-spec 的 `yeelink.light.mbulb3`）

| siid.piid | 名称 | 类型 | 范围 | 本工程 |
|---|---|---|---|---|
| `2.1` | on | bool | — | ✅ 读写，写后回推 |
| `2.2` | brightness | uint16 | 1 ~ 65535 | ✅ 读写，映射到 PWM 占空比 |
| `2.3` | color-temperature | uint32 | 2700 ~ 6500 K | ✅ 读写，**只记值**（单色灯珠表达不了） |
| `3.3` | delay-off | int16 | 0 ~ 60 分钟 | ⬜ 未实现（延时关灯） |
| `3.5` | smart-switch | int32 | 0 ~ 1 | ⬜ 未实现（断电记忆） |
| `3.11` | powerup-setting | uint32 | 枚举 | ⬜ 未实现（上电状态） |

`3.x` 那三条是插件页面上的「高级设置」，不影响基本控制。要做的话在 `b_props[]`
里加表项 + 定时器即可，链路不用改。

## 3. 串口命令

| 命令 | 作用 |
|---|---|
| `info` | PID / 绑定 / 登录 / 连接 / 开关 / 亮度 / 色温 |
| `on` / `off` | 开关（等价于 App 点开关，连着手机时回推 `properties_changed`） |
| `bright 0~100` | 按百分比调亮度，内部换算成 1~65535 |
| `ct 2700~6500` | 设色温（只记值） |
| `pid [0xXXXX]` | 查看 / 写入 PID，写后自动重启 |
| `factory` | 擦 NVS 重启（回到未绑定；**删设备重加前必须执行**） |
| `reboot` | 重启 |

按键：**短按 BOOT = 开关灯**（同样回推状态），**长按 3 秒 = 恢复出厂**。

## 4. 没有 PID 也能验证的部分

```bash
# 灯真的会亮（GPIO8 板载蓝灯，低电平点亮）
bright 100      # 全亮
bright 30       # 30%
off             # 灭

# 广播帧确实是这台设备
#   70 28 | 2b 1a | 34 | 05 71 ce 3b 00 10 | 11 | 11 10 01 00
#           PID(LE)      MAC …71:05
```

已知实测（2026-11-14）：启动横幅 / `0xFE95` 四个特征注册 / 广播 `MJDP003`（RSSI −55）/
`pid` 写入后落盘并重启生效 —— 全部通过。

## 5. 已知边界

1. **PID 未知**：只能真机扫或从米家后台查。空着时设备照常广播，但 App 看不到。
2. **色温不体现在灯上**：单颗蓝灯没有色温概念，`2.3` 只落值 + 打日志。
   要真做双色温，改成两路 PWM（暖 2700K / 冷 6500K）按 `2.3` 混合，约 30 行。
3. **Mesh 配网不支持**：多灯组网、网关语音控制、Mesh 跨设备联动都依赖 Mesh 密钥，
   本工程只做「单灯直连」这一条。
4. **删设备重加先 `factory`**：绑定过的设备广播会变成 registered 态，米家「添加」
   只认未注册帧，否则扫不到（和夜灯 2 同一个坑）。
5. **重烧固件后手机要关/开蓝牙**：Android 会缓存 GATT 服务表，句柄变了必然
   `status 133` 超时（`docs/troubleshooting.md` Q10）。

## 6. 和夜灯 2 工程的差别

| | `nightl2_adv`（夜灯2） | `bulb_gatt`（本工程） |
|---|---|---|
| 协议 | NUS 文本 `6E400001/2/3` | 标准 spec 帧（`0x0010`） |
| 绑定 | legacy token（12B）+ ag2 建链 | 0xA2 → ECDH → did → 0x11 |
| 属性 | `2.1` 亮度 / `2.2` 延时 / `2.3` 开关 | `2.1` 开关 / `2.2` 亮度 / `2.3` 色温 |
| 代码量 | 2143 行 | 734 行 |
| 难度 | 高（自定义通道 + 分帧握手） | 低（照温湿度计抄，只换属性表） |

**如果只是想验证「灯能不能被米家控制」，本工程比夜灯 2 干净得多。**
