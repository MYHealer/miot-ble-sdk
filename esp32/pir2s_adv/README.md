# pir2s_adv —— 米家人体传感器 2S 小白版

> 状态：2026-11-15 编译 + 烧录 + 广播实测通过；米家绑定待验证。
> 工程 `esp32/pir2s_adv`，约 590 行，固件 580,016 B，零告警。

## 这是什么

模拟**小米人体传感器 2S**（XMPIRO25XS，miot 型号 `xiaomi.motion.pir1`，
产品 ID 13617 = PID **`0x3531`**）的 BLE 广播固件。烧进 ESP32-C3 后，
米家 App 把它当一台真 2S 添加，短按 BOOT 就是「有人移动」。

与 `motion_adv`（人体传感器 2，0x0A8D）的核心差别：**对象号不是抄的，是算的**。

```text
eid = 0x4000 | (0x200 若是事件) | (siid << 10) | (iid - 1000)
```

公式出处：XiaomiGateway3 解码器注释（`converters/mibeacon.py`），
并用 3 Pro 的实测对象回验（0x5C01=7.1001 ✓ / 0x601D=8.1029 ✓ / 0x4801·0x4C03 ✓）。

## 本工程的对象表（由 `xiaomi.motion.pir1` spec 推导）

| eid | spec | 含义 | 格式 | 发送时机 |
|---|---|---|---|---|
| `0x4A08` | 2.e.1008 移动事件 | 有人移动，参数 = 光照 | 4B float32 lux | 短按 BOOT，连发 3 帧 |
| `0x4805` | 2.p.1005 光照度 | 环境光照 | 4B float32 lux | 双击 BOOT / 轮播 |
| `0x4818` | 2.p.1024 无人持续 | 距上次移动秒数 | 2B uint16 s | 回无人时 / 轮播 |
| `0x4835` | 2.p.1053 自定义无人时间 | 用户配置档 | 2B uint16 分（=2） | 轮播 |
| `0x4C03` | 3.p.1003 电量 | 电量 | 1B uint8 % | 轮播 |

注：spec 里还有服务 5 的 `5.p.1` 有人无人 / `5.e.1022` 推测无人，
但 piid < 1000 时 eid 公式不适用（真机如何编码未知），v1 不发；
App 的「N 分钟无动作」触发由 `0x4818` 递增驱动。

## 操作（板载 BOOT 键）

| 动作 | 效果 |
|---|---|
| 短按 | 有人移动事件（带当前光照值），连发 3 帧 |
| 双击 | 光照档位切换 5 → 50 → 300 lux |
| 长按 ≥5s | 恢复出厂（擦 NVS 重启，可重新添加） |
| 无人 60s | 自动回「无人」，0x4818 开始递增 |

## 身份参数

- PID `0x3531` / 名字 `PIR2S`
- NVS 命名空间 `pir2s`
- 派生 MAC `10:00:3B:CE:73:03`（后缀 `0x73`，避开其他工程）

## 待验证 / 已知边界

- 米家绑定后：页面是否显示「有人移动 / 光照 / 电量」三件套；
  短按是否触发自动化（判据同 V5：能绑能建但无日志 = 对象号不对）
- 光照是模拟值（三档轮换），没接真实传感器；接真传感器改 `v_lux` 一处即可
- 2S 官方要求「蓝牙 Mesh 网关」，但按 GW3 分类它走 MiBeacon2 spec 广播，
  盲网关（如小爱音箱 Play 增强版）应能收——这正是本次要验证的点
